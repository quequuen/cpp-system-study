## 가상 메모리 (Virtual Memory)

프로세스가 실제 물리 메모리(RAM)의 위치를 전혀 몰라도, 마치 자기만의 독립된 메모리 공간을 통째로 가진 것처럼 보이게 해주는 OS의 추상화 기법. [`thread.md`의 프로세스](./thread.md#프로세스-process)에서 다룬 **독립된 메모리 구조**가 실제로 격리되는 하부 메커니즘이 바로 이것.

### 논리 주소 (Logical Address) vs 물리 주소 (Physical Address)

- **논리 주소 (Logical Address)** 또는 **가상 주소 (Virtual Address)**
  CPU와 프로그램이 다루는 주소. 코드에서 포인터로 찍히는 주소(`&x` 등)는 전부 이 논리 주소임. 각 프로세스는 0번지부터 시작하는 자기만의 주소 공간을 따로 가짐.
- **물리 주소 (Physical Address)**
  실제 RAM 칩 위의 위치. 프로그램은 이 주소를 직접 알 수 없고, 알 필요도 없음.

```
Process A                   Process B
논리 주소 0x1000             논리 주소 0x1000   ← 서로 똑같은 번지를 가질 수 있음
     │                            │
     ▼ (MMU가 변환)                ▼ (MMU가 변환)
물리 주소 0x7F3A00           물리 주소 0x82C100   ← 실제로는 전혀 다른 RAM 위치
```

두 프로세스가 완전히 같은 논리 주소를 들고 있어도, 실제로 가리키는 물리 메모리는 서로 다르기 때문에 한 프로세스가 다른 프로세스의 메모리를 건드릴 수 없음 (프로세스 격리).

### MMU (Memory Management Unit)

CPU가 논리 주소로 메모리에 접근할 때마다, 그 요청을 가로채서 물리 주소로 바꿔주는 **하드웨어**. 모든 메모리 접근마다 발생하는 변환 작업이라 소프트웨어로 처리하면 너무 느리기 때문에, CPU 안에 내장된 전용 회로(CPU 패키지)가 처리함.

```
CPU가 요청한 논리 주소
      ↓
    [ MMU ]  ← 페이지 테이블을 참조해서 변환
      ↓
   물리 주소
      ↓
   실제 RAM 접근
```

### 페이지 테이블 (Page Table)

MMU가 변환할 때 참조하는 논리 주소와 매칭되는 물리 주소의 매핑 테이블. **프로세스마다 하나씩 따로 가짐.** 그래서 서로 다른 논리 주소 공간이 서로 다른 물리 주소로 매핑될 수 있는 것.

- 메모리를 바이트 단위가 아니라 **페이지(Page)**라는 고정 크기 블록 단위로 관리함. (보통 4KB, Apple Silicon은 16KB)
- 물리 메모리 쪽의 같은 크기 블록은 **프레임(Frame)**이라고 부름.
- 즉 페이지 테이블은 정확히는 **페이지 번호 → 프레임 번호**의 매핑이고, 여기에 페이지 안에서의 offset을 그대로 더해 최종 물리 주소가 나옴.

```
논리 주소 = [ 페이지 번호 | 페이지 내 offset ]
                  │              │
                  ▼ (페이지 테이블 조회)      │
            [ 프레임 번호 ]       │
                  │              │
                  ▼              ▼ (그대로 유지)
물리 주소 = [ 프레임 번호 | 페이지 내 offset ]
```

### TLB (Translation Lookaside Buffer)

페이지 테이블은 메인 메모리에 있어서, 매번 조회하면 메모리 접근이 두 번(테이블 조회 + 실제 데이터 접근) 필요해져 느려짐. TLB는 CPU 안에 있는 **최근 변환 결과를 캐싱해두는 작은 고속 캐시**. 변환하려는 페이지 번호가 TLB에 있으면(TLB Hit) 페이지 테이블 조회 없이 바로 물리 주소를 얻어 속도가 빨라짐.

---

> 페이지 단위로 메모리를 들여오고 내보내는 과정(데맨드 페이징)이나, 페이지가 부족해서 디스크로 밀어내는 과정에서 발생하는 **스래싱(Thrashing)**이 발생할 수 있음. ([`thread.md`의 멀티 스레드](./thread.md#멀티스레드))

### 페이지 폴트 (Page Fault)

CPU가 프로세스의 가상 주소에 접근했을 때, 해당 페이지를 정상적으로 처리할 수 없는 상황에서 발생하는 예외(Exception).

대표적으로 페이지 테이블에서 해당 페이지가 물리 메모리(RAM)에 존재하지 않는 경우 발생함. 이때 CPU는 OS에 제어를 넘기고, OS가 해당 상황을 처리함.

단, 페이지 폴트가 반드시 오류를 의미하는 것은 아님. 요구 페이징(Demand Paging)에 의해 아직 RAM에 올라오지 않은 페이지에 처음 접근할 때도 정상적으로 발생할 수 있음.

- 페이지 폴트 발생 과정

```
1. CPU가 가상 주소에 접근함.
2. MMU가 페이지 테이블을 확인함.
3. 해당 페이지가 RAM에 존재하지 않거나 접근 권한이 맞지 않으면 페이지 폴트가 발생함.
4. CPU가 OS의 페이지 폴트 처리 루틴(Page Fault Handler)으로 제어를 넘김.
5. OS가 페이지 폴트의 원인을 확인함.
  - 유효한 메모리 영역이지만 RAM에 없는 경우 → 디스크 등 backing store에서 페이지를 가져옴.
  - 허용되지 않은 메모리 영역에 접근한 경우 → 프로세스에 오류를 전달하거나 종료함.
6. 필요한 경우 빈 프레임을 확보하고, 페이지를 RAM으로 가져옴.
7. 페이지 테이블을 갱신함.
8. 중단되었던 명령어를 다시 실행함.
```

- 페이지 폴트의 종류
  - Minor Page Fault (경미한 페이지 폴트)
    - 디스크에서 데이터를 읽어오지 않고도 페이지 폴트를 해결할 수 있는 경우.
    - 예를 들어 이미 RAM에 존재하는 공유 페이지를 프로세스의 페이지 테이블에 연결하는 경우 등이 있음. → 물리 메모리에는 이미 데이터가 올라와 있는데, 현재 프로세스 테이블에는 아직 그 메모리와 연결된 정보가 없는 상태.
  - Major Page Fault (심각한 페이지 폴트)
    - 필요한 데이터를 디스크 등의 저장 장치에서 읽어와야 하는 경우.
    - RAM에 페이지를 올리는 과정에서 상대적으로 큰 I/O 비용이 발생함.

- 페이지 폴트와 세그멘테이션 폴트의 차이
  - `Page Fault`
    - 가상 주소 접근 과정에서 발생하는 예외.
    - 정상적인 메모리 접근에서도 발생할 수 있으며 OS가 처리한 후 실행을 이어갈 수 있음.
  - `Segmentation Fault`
    - 프로세스가 허용되지 않은 메모리 영역에 접근했을 때 발생하는 오류.
    - OS가 접근 위반으로 판단하면 일반적으로 프로세스에 SIGEGV를 전달함 (Linux 기준).

즉, 페이지 폴트는 하드웨어와 OS가 메모리 접근 과정에서 처리하는 예외이고, 세그멘테이션 폴트는 잘못된 메모리 접근으로 인해 발생하는 오류임.

## 메모리 접근 권한 (Memory Protection)

운영체제가 프로세스의 메모리 영역마다 접근할 수 있는 권한을 설정하여, 허용되지 않은 읽기·쓰기·실행을 방지하는 메커니즘.

페이지 테이블에는 각 페이지의 물리 메모리 매핑 정보뿐 아니라 접근 권한 정보도 함께 저장됨. MMU는 CPU가 메모리에 접근할 때 해당 권한을 확인하고, 허용되지 않은 접근이면 예외를 발생시킴.

### 메모리 접근 권한의 종류 (RWX)

- **R (Read)**: 읽기 권한. 메모리에 저장된 데이터를 읽을 수 있음.
- **W (Write)**: 쓰기 권한. 메모리에 저장된 데이터를 수정할 수 있음.
- **X (Execute)**: 실행 권한. 메모리에 저장된 명령어를 CPU가 실행할 수 있음.

### 메모리 영역별 일반적인 권한

프로세스의 메모리 영역은 용도에 따라 서로 다른 접근 권한을 가짐.

| 메모리 영역 | 일반적인 권한 | 설명                                                     |
| ----------- | ------------- | -------------------------------------------------------- |
| Code (Text) | R-X           | 프로그램의 기계어 명령어가 저장되는 영역                 |
| Data        | RW-           | 초기화된 전역 변수와 정적 변수가 저장되는 영역           |
| BSS         | RW-           | 초기화되지 않은 전역 변수와 정적 변수가 저장되는 영역    |
| Heap        | RW-           | 동적으로 할당한 메모리가 저장되는 영역                   |
| Stack       | RW-           | 함수의 지역 변수, 매개변수, 반환 주소 등이 저장되는 영역 |

※ 일반적인 예시이며 운영체제, 컴파일러, 프로그램 설정에 따라 달라질 수 있음.

### 접근 권한 위반 (Access Violation)

CPU가 메모리에 접근할 때 MMU가 페이지 테이블의 권한을 확인함.

허용되지 않은 작업을 수행하면 페이지 폴트 예외가 발생하고, OS가 이를 처리함.

예를 들어 읽기 전용인 Code 영역에 데이터를 쓰려고 하면 쓰기 권한 위반이 발생함.

```cpp
char* code = (char*)0x주소;
*code = 'A';  // 해당 메모리가 읽기 전용이면 접근 권한 위반
```

실제 접근 권한은 해당 주소가 유효한 매핑인지, 어떤 권한이 설정되어 있는지에 따라 달라짐.

### DEP / NX (Data Execution Prevention / No-eXecute)

메모리 영역에 실행 권한(X)을 제한하여 데이터 영역에 저장된 명령어가 실행되는 것을 방지하는 보안 기술.

예를 들어 Stack이나 Heap 영역은 일반적으로 읽기와 쓰기는 허용하지만 실행은 허용하지 않음(RW-).

공격자가 Stack에 악성 코드를 삽입하더라도 해당 영역에 실행 권한이 없다면 CPU가 코드를 실행하지 못하도록 차단함.

- DEP: Windows에서 사용하는 데이터 실행 방지 기능의 명칭.

- NX: 메모리 페이지를 실행 불가능하게 설정하는 하드웨어 지원 기능.

### W^X (Write XOR Execute)

하나의 메모리 영역에 쓰기 권한(W)과 실행 권한(X)을 동시에 부여하지 않는 보안 원칙.

즉, 메모리 영역은 쓰기가 가능하거나 실행이 가능해야 하며, 일반적으로 두 권한을 동시에 허용하지 않음.

- RW- : 읽기와 쓰기는 가능하지만 실행은 불가능.

- R-X : 읽기와 실행은 가능하지만 쓰기는 불가능.

이를 통해 메모리에 코드를 삽입한 후 실행하는 공격을 어렵게 만들 수 있음.

### ASLR (Address Space Layout Randomization)

프로세스가 사용하는 메모리 영역의 시작 주소를 실행할 때마다 무작위로 배치하는 보안 기술.

공격자가 특정 메모리 주소를 이용해 공격하려면 해당 주소를 알아야 하는데, ASLR은 메모리 배치를 무작위화하여 주소 예측을 어렵게 만듦.

```
주요 대상:

Stack
Heap
공유 라이브러리
실행 파일의 코드 영역 (PIE가 적용된 경우)
```

DEP/NX가 메모리에서 코드 실행을 제한하는 기술이라면, ASLR은 메모리 주소 예측을 어렵게 만드는 기술임.
